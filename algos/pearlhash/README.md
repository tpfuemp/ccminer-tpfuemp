# pearlhash - Pearl (PRL)

`-a pearlhash` (alias `pearl`). Pearl's proof of work is "proof of useful work":
the hash is a by-product of an int8 matrix multiplication (NoisyGEMM). On a pool
there is no useful work involved: the miner chooses its own matrices, so this is a
classic proof of work whose cost is an int8 GEMM. **The hashrate is shown in int8
multiply-accumulates per second (MAC/s)**, which is the unit Pearl pools display
("TH/s").

## Provenance

New port (2026-10). Written from the coin's reference implementation,
pearl-research-labs/pearl at commit `0798903` (ISC):

- `zk-pow/src/ffi/mine.rs` (`try_mine_one`): the mining loop;
- `zk-pow/src/api/seed.rs`, `api/proof_utils.rs`: seeds, serializers, nbits, the
  ticket hash;
- `zk-pow/src/circuit/pearl_noise.rs`: the noise generator;
- `zk-pow/src/api/sanity_checks.rs`: the difficulty bound and the rank penalty;
- `pearl-blake3/src/merkle.rs`, `zk-pow/src/ffi/plain_proof.rs`: the Merkle
  proofs and the PlainProof a share carries.

Files:

- `pearl_ref.h`: host reference, used for the self-test and to re-verify every
  candidate on the CPU. Checked against vectors generated by the Rust reference:
  every noise byte, every tile.
- `pearl_proof.h`: BLAKE3 Merkle trees, multi-leaf proofs, and the bincode
  PlainProof. Byte-identical to the reference miner's own proofs.
- `pearl_device.cuh`: the noise, operand and GEMM kernels.
- `pearlhash.cu`: scanhash, self-test, and the proof stash for submission.
- BLAKE3 comes from the shared `cuda/blake3_device.cuh` (keyed mode and the full
  tree were added for this port).

## Consensus definition (certificate V3, dense)

```
job_key  = BLAKE3(header76 | config52)                header76: no nonce, wire order
hash_a   = BLAKE3_keyed(pad1024(A row-major),  job_key)    = the Merkle root of A
hash_b   = BLAKE3_keyed(pad1024(B^T row-major), job_key)
hash_a'  = BLAKE3_keyed(hash_a | le32(m) | 0^28, key = SEED_SALT_A)   (V3 "salted")
hash_b'  = BLAKE3_keyed(hash_b | le32(n) | 0^28, key = SEED_SALT_B)
b_seed   = BLAKE3(job_key | hash_b'),  a_seed = BLAKE3(b_seed | hash_a')
E_A, E_B = rank-r noise from the seeds (uniform [-32,31] x sparse +1/-1)
C        = (A + E_A)(B + E_B)        int7 x int7 -> int32, A, B in [-64, 63]
```

- The output is cut into **hash tiles** by two periodic index patterns, which the
  miner chooses and commits in `config52`. Each tile is one ticket.
- After every r-chunk of k, the XOR of the tile's running sums is folded into a
  16-word jackpot: `jp[c % 16] = rotl(jp[c % 16], 13) ^ x`.
- The ticket hash is `BLAKE3_keyed(jackpot, key = a_seed)`. It is read as a
  little-endian U256 and accepted if `<= target x h*w*(dot/r)*128`. The factor is
  the work in one ticket, so difficulty is per MAC.
- A share is a **PlainProof**: m, n, k, rank, plus Merkle multi-proofs of the
  tile's rows of A and B^T. The pool re-derives everything from it and builds the
  ZK proof for blocks itself.

## GPU implementation

- **This miner's choices:** m = n = 8192, k = 2048, rank 128 (the consensus
  minimum; rank 128 also means no rank penalty), and A = 0.
- **The nonce:** B^T is all zero except its first 1024-byte chunk, which carries
  (trial, a per-job salt, GPU id) as int7 digits.
- **Per trial (2^37 MAC):** the host updates hash_b along one Merkle path (14
  BLAKE3 nodes) and derives the seeds. The GPU then runs the noise kernels, the
  operand prepass, and one fused GEMM + jackpot + ticket-hash kernel.
- **Kernel by architecture:**

| arch | kernel | pattern (rows x cols) | one thread's tile |
|---|---|---|---|
| sm_80+ | `pearl_tiles_imma_kernel` (mma.sync m16n8k32 s8, 3-stage cp.async) | `[0,8,...,56]` x `[0,1,8,9,16,17,24,25]` | its 4x4 MMA accumulators |
| sm_61, sm_75 | `pearl_tiles_dp4a_kernel` (8x8 register blocking, dp4a) | `[0,1,2,3,64..67]` x same | its 8x8 register block |

Each kernel's pattern is exactly one thread's register block, so the jackpot fold
needs no communication between threads. Both patterns are accepted by the
reference verifier.

- **Re-verify:** every reported tile is recomputed on the CPU (only its 8 + 8
  rows) before its proof is built. A kernel defect can only cause a local
  reject, never a bad share.
- **Proof size:** a share is about 34 KB, or 46 KB of base64.
- **Memory:** about 100 MB of GPU memory and about 33 MB of host memory per GPU.

## Pool protocol

Luckypool-style stratum, newline-delimited JSON with **named** params:

- **Authorize:** `mining.authorize {wallet, pass, agent}`. There is no
  `mining.subscribe` and no extranonce.
- **Notify:** `mining.notify {header (76 bytes hex), height, job_id, target}`.
  - `target` is a big-endian 256-bit base share target, which the miner scales
    by its own work factor.
  - A `cert_version` other than 3 is refused: the job is parked and logged
    instead of mined.
- **Submit:** `mining.submit {job_id, plain_proof (base64)}`.
- **Errors** are `{code, msg}`. 21 = stale, 22 = duplicate, 23 = low difficulty,
  26 = invalid proof.
- **Difficulty changes:** a vardiff retarget re-sends the same header under a
  new job id. The miner switches to the new id and keeps its position.

Pools differ in the username form (`wallet.worker` or `wallet/worker`); use
the one your pool documents.

## Self-test

At startup:

- **Host KATs** pinned from the Rust reference: the seed chain, noise bytes, and
  one jackpot -> ticket hash.
- **GPU differential:** the kernel against the host reference on all 1024
  tiles of a 256 x 256 trial.
- **Negative control:** a changed seed must change every tile.

A mismatch refuses to start. For testing only, `PEARLHASH_SELFTEST_FAULT=1`
(host KAT) or `2` (GPU) breaks one check on purpose, to show that it fires.
`PEARLHASH_DUMP=<dir>` writes the first share as `proof.bin` + `header76.hex`,
for checking against the reference verifier.

With `-D`, the miner logs a per-trial time split every 10 s: host + launch, GPU,
share path.

## Limits

- **Certificate V3 only.** A protocol fork to FP8 certificates (Pearl's draft
  PIP-3: Hopper/Blackwell only) would end mining on these cards. The miner refuses
  such jobs instead of producing invalid shares.
- Solo mining (getblocktemplate) is not supported, since a block needs the ZK
  prover. Use a pool.
- Not every pool honours a requested difficulty in the password (`-p d=N`).
