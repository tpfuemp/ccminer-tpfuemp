# bc3hash - Bitcoin III (BC3Hash, from block 64 360)

`-a bc3hash` (alias `bc3`). Bitcoin III switched its proof of work from SHA3-256T
(`-a sha3t`) to BC3Hash at block 64 360.

## Provenance

New port (2026-10): a CUDA implementation, with the coin's own code as the host
oracle for the self-test, the `-D` differential and the re-verification of
every candidate.

- **Consensus (authoritative):** BitcoinIII Core v31.1.2 (commit `ac3dbe8b47`),
  `src/crypto/bc3/`. MIT, see `ref/COPYING`.
- **Host oracle, `ref/`:** generated by `ref/vendor.py`; do not hand-edit. Six
  files are verbatim. Two are patched because the coin needs `unsigned __int128`
  and gcc builtins, which MSVC lacks:
  - `uint.hpp` gets a 128-bit shim (`bc3_shim.h`).
  - `mix.cpp` gets a portable prefetch, and Fermat in place of the binary-Euclid
    `inverse256`. The result is the same, including `inverse256(0) == 0`.

  The patched build matches the unpatched coin sources bit for bit, and the
  coin's test vectors pass.
- **secp256k1:** the copy vendored for curvehash (`algos/curvehash/secp256k1`),
  plus curvehash's device field/group code.
- `bc3hash_oracle.cpp` builds `ref/` as one C++17 translation unit.

## Consensus definition

```
D    = "BC3Hash-BlockHash-Algorithm/BitcoinIII-PoW/2026"
H    = header80 (nonce at bytes 76..79)

s512 = SHA3-512   (D | "/SHA3-512"   | H)
s384 = SHA3-384   (D | "/SHA3-384"   | H)
sh   = SHA-512    (D | "/SHA-512"    | H)
r160 = RIPEMD-160 (D | "/RIPEMD-160" | H)
bs   = BLAKE2s-256(D | "/BLAKE2s"    | H)   personalization 0a20e811610908ba
bb   = BLAKE2b-512(D | "/BLAKE2b"    | H)   personalization 1e80f2fddc5818d6fe9b581e3bd4930b
mix  = bc3mix512(s512)                                  // >99% of the work
hash = SHA3-256(D | "/SHA3-256" | s384 | mix | sh | r160 | bs | bb)
```

`bc3mix512` runs four phases over a 1 KB message schedule:

- **A:** 32 rounds of 64-bit fixed-exponent modexps and fixed-base powers.
- **B:** 16 rounds of the same at 128 bits.
- **C:** 16 rounds at 256 bits, each with four modexps and four fixed-base
  secp256k1 scalar multiplications (bases H, J, K, L).
- **D:** 64 rounds of fixed-base powers and one inversion mod 2^256 - 36113 each.

The moduli are pseudo-Mersenne 2^(64L) - c:
- c in {59, 159, 189} for the exponentiations;
- c in {1469, 15449, 36113} for the power tables and the inversion.

- **Version bit 11** selects BC3Hash in the header. Pool jobs carry it, and the
  miner never masks or rolls the version.
- The digest bytes go into `hash[8]` as-is (little-endian words, word 7 most
  significant), followed by a full 256-bit compare.
- Stratum: default sha256d merkle, default submit byte order, difficulty
  factor 1 (`diff * 2^32`), as for sha3t.

## GPU implementation

One thread per nonce, three kernels per batch, with the state in global memory
(SoA, about 0.8 KB per nonce):

| kernel | work |
|---|---|
| `bc3_k_front_ab` | the six front hashes, the schedule, phases A and B |
| `bc3_k_c` | phase C |
| `bc3_k_d_final` | phase D, the final SHA3-256, the target compare and report |

The device code lives in `cuda/`:

- `bc3_uint_device.cuh`: 32-bit-limb integers and the modular multiply.
- `bc3_exp_device.cuh`: fixed exponents, fixed-base powers, `inverse256`.
- `bc3_ec_device.cuh`: 16-bit-window fixed-base curve multiplication, and the
  table builder.
- `bc3_mix_device.cuh`: the four phases.
- `bc3_hashes_device.cuh`: SHA3, SHA-512, RIPEMD-160 and BLAKE2s/b with
  personalization.
- `bc3_constants.cuh`: generated by `gen_constants.py`; do not hand-edit.

Tables, per GPU:
- pow tables, 336 KB, built by the oracle;
- curve tables, 4 x 64 MB, built on the device at startup.

`bc3hash.cu` is built with a 255-register cap in both build systems; the
project default is 128. The default batch is 65 536 nonces (`-i` to tune).

The kernel reports the two lowest candidates. The host re-hashes both with the
oracle before submitting, so a kernel defect can only cause a local reject,
never a bad share.

## Self-test and `-D`

At startup a self-test checks the tables, the coin's test vectors, the
candidate report, a negative case and a 64-nonce scan. A mismatch refuses to
start.

With `-D`, a GPU-vs-CPU differential runs on the live job: 251 nonces, once per
new block and otherwise at most once a minute. A mismatch stops the miner.

For testing only, `BC3HASH_SELFTEST_FAULT=tables|kat|report|neg|scan|cuda` and
`BC3HASH_DIFF_FAULT=1..4` break one check on purpose, to show that it fires.
