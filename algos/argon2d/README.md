# Argon2 family (`-a argon2d500`, `argon2d1000`, `argon2d4096`, `argon2d16000`, `argon2id1024`)

Memory-hard Argon2 proof-of-work. Five coins share this folder — a single
Argon2 hash over the 80-byte header (password = salt = header, outlen = 32),
differing only in the Argon2 cost parameters, version and type:

| algo         | coin               | m_cost (KiB) | lanes | t_cost | version | type |
|--------------|--------------------|--------------|-------|--------|---------|------|
| argon2d500   | Dynamic (DYN)      | 500          | 8     | 2      | 0x10    | d    |
| argon2d1000  | Zero Dynamics Cash | 1000         | 8     | 2      | 0x10    | d    |
| argon2d4096  | Argentum / Myriad  | 4096         | 1     | 1      | 0x13    | d    |
| argon2d16000 | Alterdot           | 16000        | 1     | 1      | 0x10    | d    |
| argon2id1024 | Bitweb (BTW)       | 1024         | 1     | 3      | 0x13    | **id** |

## Argon2id vs Argon2d

Argon2**d** picks each reference block from the previous block's first word —
data-*dependent* addressing, everywhere. Argon2**id** is a hybrid: pass 0,
slices 0 and 1 use Argon2**i**-style data-*independent* addresses generated by
a pseudorandom address block, and everything after that is Argon2d. The type
is also hashed into H0, so an Argon2id instance differs from an Argon2d one
with identical cost parameters from the very first block.

Bitweb is the first coin here with `t_cost > 1` *and* version 0x13, so it is
also the first to exercise the v1.3 overwrite rule (below).

## Layout

- `argon2d.cu` — the per-coin variant table (`argon2d_variant`), CPU reference
  hashes (`argon2d*_hash` / `argon2id1024_hash`, used to re-verify every GPU
  candidate before submit), the shared `scanhash_argon2d` driver and the
  init-time self-test.
- `argon2d_fill.cu`, `blake2b_kernels.cu` — the GPU fill and BLAKE2b kernels.
- `argon2d_kernel.h`, `cudaexception.h` — device-side headers.
- `argon2ref/` — the vendored Argon2 reference implementation. `argon2.c`,
  `core.c`, `encoding.c`, `opt.c`, `thread.c` and `blake2/blake2b.c` are built;
  `run.c` / `test.c` / `bench.c` / `genkat.c` / `ref.c` ship with the upstream
  reference but are not compiled here.

> Note: `rinhash/argon2d_device.cuh` is a separate, rinhash-owned Argon2d device
> header and is unrelated to this folder.

## Variant coexistence (runtime geometry)

The kernels used to be compiled for exactly one `(m_cost, lanes, t_cost,
version)` tuple via `ALGO_*` enum constants, so only one coin per build could
be GPU-correct. The full parameter set (m_cost, lanes, passes, version, type,
total/segment blocks) is now passed to `argon2_initialize` / `argon2_fill` /
`argon2_finalize` as runtime kernel arguments — the heavy `argon2_fill` kernel
always took most of it that way — so all variants are GPU-correct in one
binary at no measurable cost (the parameterized kernels are a tiny fraction of
the pipeline, and the two branches `type`/`version` select are warp-uniform
and loop-invariant per slice).

Two device-code subtleties this required:

- **lanes < 8**: the fill kernel's final-block epilogue (XOR of each lane's
  last-column block, staged in the shared cache) hardcoded 8 lanes and 256
  threads. It now XORs `lanes` rows with a stride loop over the block's
  `lanes*32` threads — bit-identical for lanes=8, and it is what made the
  lanes=1 coins (argon2d4096, argon2d16000) work on GPU at all. argon2d16000
  had never produced a valid GPU share in this fork before this fix (its
  false candidates were silently discarded by the host re-verify).
- **Last-column/cache aliasing race (donor-era wrong-hash bug, fixed)**: the
  donor kernel staged the final pass's last-column block into shared slot
  `c[lane][0]` for the epilogue XOR — the same slot that caches column 2.
  Cross-lane refs to column 2 are legal within the final slice, and there is
  no barrier until the slice ends, so a lane that finished early could serve
  another lane its final block instead of column 2 → a wrong (but
  deterministic-per-race-outcome) hash for that nonce. Symptoms: sporadic
  "does not validate on CPU!" on live pools (~0.3% of nonces affected;
  harmless for share validity thanks to the host re-verify, but lost work)
  present since the donor and invisible until the warning was added. Fix:
  the last column is stored to global like every other ≥8 column and the
  epilogue XOR reads it from global (after the block-wide `__syncthreads`);
  the column-2..7 cache is untouched. Proven by a 100-iteration same-batch
  stress harness: 86/100 iterations produced the same wrong candidate before
  the fix, 0/300 after, with legit candidates perfectly deterministic.
- **Dynamic shared-cache sizing** (the lanes=1 throughput fix, ~2.8×): the
  fill kernel's shared staging used to be a static 48 KB `c[8][6]`, which
  capped occupancy at 2 blocks/SM regardless of lanes — for 32-thread lanes=1
  blocks that is 64 threads/SM (~4%), the reason argon2d4096 ran at a third
  of what the card can do. The cache is now `extern __shared__`, sized
  `lanes * 6` blocks at launch: lanes=8 keeps its 48 KB (and its cache hits —
  columns 2..7 are 10% of argon2d500's refs; removing the cache outright
  measured −10%/−6% on 500/1000), lanes=1 takes 6 KB and reaches the
  16-blocks/SM hardware cap. Measured (RTX 3060): argon2d4096 13.6 → 38.0
  kH/s (2.8×, parity with CryptoDredge 0.26.0), argon2d16000 3.2 → 7.9 kH/s
  (2.5×), argon2d500/1000 unchanged. The fill kernel's per-kernel splits are
  loggable with `-D` (init/fill/final percentages every 20 batches).
- **Argon2 version 0x13** (argon2d4096, argon2id1024): the version number is
  hashed into H0 by `argon2_initialize`, so it must be per-variant. The
  v1.0-vs-v1.3 difference inside the fill core is the *overwrite rule*: on
  every pass after the first, v1.3 computes `B[i] = B[i] XOR G(B[i-1],
  B[ref])` where v1.0 just overwrites. It never triggers at t_cost=1, which
  is why the four Argon2d coins never needed it; argon2id1024 (t_cost=3,
  v0x13) is the first variant that does, and `argon2_core` now takes the
  branch (see `argon2ref/opt.c` `fill_block` `with_xor`).
- **Argon2id addressing** (argon2id1024): for pass 0, slices 0..1,
  `argon2_step` takes J1/J2 from a generated address block instead of from the
  previous block. `next_addresses()` had been in `argon2d_fill.cu` unused since
  the argon2-gpu donor; what was missing was the `thread_input` seed/advance
  state machine around it. One address block covers 128 offsets, so
  argon2id1024's 256-block segments regenerate once, at offset 128.
- **⚠️ The v1.3 read must respect the shared cache.** Columns 2..7 live *only*
  in the shared staging cache; their global slots are never written by
  `argon2_core`, and for lanes=1 they are not even empty — `fillFirstBlock`
  derives `row = threadIdx.x / lanes` over 16 threads, so it writes 16
  first-blocks into global slots 0..15 instead of 2, leaving well-formed
  garbage in 2..15. Harmless while nothing read them, but the v1.3 rule reads
  the block it is about to overwrite, so `argon2_core` takes the old value from
  shared for `curr_index` 2..7 and from global otherwise, mirroring the store
  side. Getting this wrong silently poisons every pass after the first.

## Provenance

Donor: `duality-solutions/Dynamic-GPU-Miner-Nvidia` (this fork's `argon2d/`
descends from it; `argon2d_fill.cu` was byte-identical before the
parameterization). Dynamic's chain params verified against the donor;
argon2d4096's (4096/1/1/v0x13) against cpuminer-opt's
`algo/argon2d/argon2d-gate.c` (`register_argon2d4096_algo`).

The Argon2id addressing and v1.3 overwrite logic were transcribed from
Ondrej Mosnáček's `argon2-gpu` (`lib/argon2-cuda/kernels.cu`, MIT) — the same
upstream this folder descends from, via the copy vendored in
`cpuminer-bitweb`, whose `argon2_kernel_oneshot` matches our kernel shape.
argon2id1024's parameters (1024/1/3/v0x13/Argon2id) are from cpuminer-bitweb's
`register_argon2id1024_algo`, confirmed against Bitweb mainnet block 76523.

## Validation

- Init-time self-test: `argon2d500_hash`, `argon2d1000_0dync_hash`,
  `argon2d4096_hash` and `argon2id1024_hash` over a fixed 80-byte header must
  match digests from the independent official argon2 library (argon2-cffi,
  per-variant type and version), plus a one-bit-flip negative test proving the
  comparison isn't vacuous.
- argon2id1024 carries three extra legs and is the only variant that **fails
  closed** (the miner exits rather than mine a chain it cannot hash):
  1. Bitweb mainnet block 76523's header and Argon2id PoW hash — pins consensus
     and the emitted byte order; reversed it satisfies the block's nBits target
     `0x1d2b85a2`, so the parameters are proven, not just matched;
  2. `sha256d` of that header vs the block hash `11cd1ff6…b903`, so a mistyped
     byte reports "KAT header is corrupt" instead of "argon2 is broken";
  3. the RFC 9106 §5.3 vector (t=3, m=32, p=4, with secret and associated
     data) — proves the library is standard Argon2id.
- The host `argon2d*_hash` re-verifies every GPU candidate before submit; a
  candidate that fails re-verify logs "does not validate on CPU!" plus an
  `argon2d replay:` line with the exact 80-byte input for offline analysis.
- Loosened-target benchmark battery (RTX 3060, 2026-07-18, re-run after the
  race fix): every GPU candidate CPU-validated, zero mismatches —
  argon2d4096 1210/1210, argon2d500 750/750, argon2d1000 705/705,
  argon2d16000 334/334; plus the 100-iteration same-batch stress on the three
  live-captured race inputs (0/200/100 candidates, all deterministic, zero
  wrong). Steady-state benchmark rates (warm card): argon2d500 ~189 kH/s,
  argon2d1000 ~85-88 kH/s, argon2d4096 ~36.4 kH/s, argon2d16000 ~7.6-7.9
  kH/s (the race fix costs <1% by traffic accounting).
- **GPU-vs-CPU digest differential** (`-D`, first job, 64 consecutive nonces,
  all 32 bytes compared): the pre-submit re-verify only sees candidates, so it
  cannot catch a kernel that *misses* valid nonces — this can. Re-run it after
  any change to the three kernels. 2026-08-03, RTX 3060: **64/64 on all five
  variants**, so the Argon2id device changes are inert for the Argon2d ones.
- argon2id1024 (2026-08-03, RTX 3060, full rebuild): benchmark **39.4 kH/s**
  cool / 38.2–38.7 warm, split init 1.3% / fill 98.7% / final 0.1%; the other
  four unchanged (500: 193.4, 1000: 87.8, 4096: 37.7–37.8 kH/s). The
  fail-closed self-test was checked by corrupting one KAT header byte —
  "KAT header is corrupt" + a per-leg breakdown + exit 3, while `-a argon2d4096`
  still started. **Live-validated on a Bitweb pool: block 79368, 4/4 accepted,
  0 rejects, 39.77 kH/s.** Bitweb needs no algo-specific submit handling — it
  uses the default LE nonce / LE ntime path like the four Argon2d coins.
- Live-validated on zpool (2026-07-18, RTX 3060, after the optimization and
  the race fix, all four variants in one session): argon2d500 22/22
  (~193 kH/s), argon2d1000 44/44 (~87 kH/s), argon2d4096 35/35 (~37.6 kH/s),
  argon2d16000 32/32 (~7.3 kH/s, the first live shares this variant ever
  produced on GPU in this fork) — 133 accepted, 0 rejects, 0 re-verify
  failures (the pre-fix kernel threw ~2 "does not validate" per minute on
  argon2d500). An earlier same-day session also validated argon2d4096 across
  a mid-run pool coin switch (two distinct chains).
